# Nomi 设置中心设计规格

## 1. 背景

当前 Web 工作台同时存在两套配置导航：

- 桌面侧栏直接展示个人搜索、记忆治理、主动建议、采集状态、账号连接和 Web Search。
- 移动端齿轮下拉框同时混放日程、求职、配置和治理入口。

这导致工作入口与配置入口边界不清、同一功能重复出现，并且设置下拉框随着功能增加会持续变长。此次改造将配置类功能集中到一个独立的“设置”详情页，同时保留原有功能、API 调用和深链接能力。

## 2. 目标

1. 主导航只承担高频工作区切换，不再直接罗列配置功能。
2. 齿轮下拉框提供少量高频快捷入口，并能进入完整设置详情页。
3. 设置详情页统一承载八个配置与治理功能。
4. 桌面端与移动端使用同一套设置路由和功能面板。
5. 调整导航结构时不改变现有功能面板的 DOM id、数据加载函数和后端 API。
6. 旧的配置深链接继续可访问，避免已有链接或 Android 跳转失效。

## 3. 非目标

- 不重写主动建议、记忆治理、个人搜索、Web Search、采集、账号、助理身份和隐私管理的业务逻辑。
- 不修改这些功能使用的后端 API、数据结构或权限规则。
- 不新增设置搜索、用户偏好同步、主题切换或多用户权限体系。
- 不将日程和求职变成设置项；它们仍是独立工作区。

## 4. 信息架构

### 4.1 主导航

桌面侧栏仅保留四个入口，顺序固定为：

1. 对话
2. 日程
3. 求职
4. 设置

“设置”进入 `settingsView`，对应 `#settings`。

### 4.2 齿轮快捷菜单

移动端顶部齿轮继续作为快捷菜单开关。菜单只保留：

1. 日程管理
2. 求职助手
3. 设置

点击“设置”关闭快捷菜单并进入 `settingsView`。设置菜单不再直接罗列八个配置功能，避免形成第二套完整导航。

### 4.3 设置详情页

设置详情页包含二级导航和内容区。八个功能按以下分组展示：

#### 智能与记忆

- 主动建议：`suggestionsView`
- 个人搜索：`searchView`
- 记忆治理：`governanceView`

#### 数据与账号

- 采集状态：`collectorsView`
- 账号连接：`toolsView`
- 助理身份：`assistantIdentitiesView`

#### 能力与隐私

- Web Search：`webSearchSettingsView`
- 隐私管理：`privacyView`

设置首页默认选中“主动建议”。首次进入 `#settings` 时显示该面板；通过旧深链接进入具体面板时，设置容器同步选中对应二级入口。

## 5. 页面结构

### 5.1 复用原则

现有八个功能面板的 id 和内部表单 id 保持不变，以保证 `app.js` 中的查询、事件绑定和数据加载函数继续有效。改造只增加设置容器，并将这些面板在 DOM 层级上放入设置内容区域。

核心结构如下：

```html
<section id="settingsView" class="view settings-view">
  <header class="view-header settings-view-header">
    <div>
      <h2>设置</h2>
      <p class="view-subtitle">管理 Nomi 的记忆、数据源、外部能力与隐私。</p>
    </div>
  </header>

  <div class="settings-layout">
    <nav class="settings-navigation" aria-label="设置导航">
      <!-- 分组与二级入口 -->
    </nav>
    <div class="settings-content">
      <!-- 原有八个功能面板 -->
    </div>
  </div>
</section>
```

八个子面板不再同时作为 `.workspace` 的顶层 `.view`。它们改为 `.settings-section`，由设置路由控制 `active` 状态。每次只显示一个设置子面板。

### 5.2 桌面布局

- 设置页标题位于内容区顶部。
- 二级导航宽度固定在 220 至 240 像素之间。
- 二级导航与内容区并排显示，内容区占据剩余空间。
- 分组标题使用克制的小号文本；入口使用紧凑列表按钮，不使用大卡片。
- 二级导航和内容区分别允许纵向滚动，页面整体不产生横向滚动。

### 5.3 移动布局

- 设置页标题保留在顶部。
- 二级导航改为顶部横向可滚动的紧凑标签栏。
- 分组标题隐藏，但每个入口保留清晰名称。
- 设置内容占满剩余可用高度。
- 输入框、按钮和内容列表不得超出屏幕宽度。
- 切换设置项不打开新的浮层，不遮挡原内容。

## 6. 路由与导航行为

### 6.1 路由表

新增：

```text
settingsView -> #settings
```

保留现有子功能哈希：

```text
#suggestions          -> settingsView / suggestionsView
#search               -> settingsView / searchView
#governance           -> settingsView / governanceView
#collectors           -> settingsView / collectorsView
#tools                -> settingsView / toolsView
#assistant-identities -> settingsView / assistantIdentitiesView
#web-search           -> settingsView / webSearchSettingsView
#privacy              -> settingsView / privacyView
```

### 6.2 路由状态

路由解析返回两个维度：

- `primaryViewId`：对话、日程、求职或设置。
- `settingsSectionId`：当主视图为设置时，对应的设置子面板。

进入旧的设置子功能哈希时，主导航高亮“设置”，设置二级导航高亮相应入口。进入 `#settings` 时，默认子面板为主动建议，但 URL 保持 `#settings`，直到用户主动切换二级入口。

### 6.3 点击行为

- 主侧栏点击“设置”：进入 `#settings`，显示默认设置项。
- 齿轮菜单点击“设置”：关闭菜单并进入 `#settings`。
- 设置二级入口点击：切换子面板并写入该子面板的既有哈希。
- 浏览器前进/后退：恢复主视图和对应设置子面板。
- 子面板中的“返回设置”按钮移除；用户通过始终可见的设置二级导航切换功能。
- Android 或外部链接直接打开旧哈希时，仍进入正确设置项。

## 7. 数据加载

设置子面板沿用现有按需加载：

- 主动建议调用 `loadSuggestions`。
- 个人搜索由用户提交搜索表单后调用 `loadSearch`。
- 记忆治理调用 `loadGovernance`。
- 采集状态调用 `loadCollectors`。
- 账号连接调用 `loadTools`。
- 助理身份调用 `loadAssistantIdentities`。
- Web Search 调用 `loadWebSearchSettings`。
- 隐私管理保留现有本地状态和提交行为。

切换到设置首页默认项时，只加载主动建议，不预加载其他七个面板。这样不会因为进入设置页同时请求所有 API。

## 8. 状态与错误处理

- 子面板加载失败时继续使用该面板现有的错误提示，不影响设置导航。
- Web Search API Key 输入框在离开 Web Search 面板时继续清空。
- 实时主动消息到达时，不抢占用户当前设置页或设置子面板。
- 未识别的哈希仍回退到对话页。
- 某个设置 DOM 节点缺失时，导航切换不得抛出未捕获异常。

## 9. 可访问性

- 设置二级导航使用 `nav` 和明确的 `aria-label`。
- 当前设置入口使用 `aria-current="page"`。
- 移动端横向导航可通过键盘聚焦和滚动。
- 每个入口名称必须是可见文本，不依赖图标表达含义。
- 主侧栏与设置二级导航分别拥有独立、明确的导航标签。

## 10. 测试与验收

### 10.1 自动化测试

静态工作台测试必须验证：

1. 主侧栏只保留对话、日程、求职和设置。
2. 齿轮菜单只保留日程、求职和设置。
3. 设置详情页包含三个分组和八个指定功能。
4. 八个原有功能面板及内部关键 DOM id 仍存在。
5. `#settings` 和八个旧深链接均能映射到正确主视图与子面板。
6. 点击设置二级入口更新哈希并触发原有按需加载函数。
7. 浏览器后退能恢复前一个设置项。
8. 实时消息不会把设置页切回对话。
9. 离开 Web Search 时仍清除 API Key 明文输入。
10. 桌面和移动 CSS 均定义设置导航与内容布局，不产生横向溢出。

测试遵循 TDD：先更新静态契约测试并确认因新结构缺失而失败，再修改 HTML、JavaScript 和 CSS 使其通过。

### 10.2 人工验收

桌面端：

- 侧栏只显示四个主入口。
- 点击设置后能在八个设置项间切换。
- 每个设置项能加载真实数据、刷新或提交现有表单。
- 地址栏深链接与当前高亮一致。

移动端：

- 齿轮菜单只有三个快捷入口。
- 点击设置进入独立详情页，不出现覆盖内容的长菜单。
- 横向设置导航可滚动，八个入口均可到达。
- 账号连接和 Web Search 等长内容可正常纵向滚动。
- 返回键和浏览器历史不会进入空白页或错误面板。

## 11. 完成标准

满足以下条件才算完成：

- 主导航、齿轮菜单和设置详情页的信息架构与本规格一致。
- 八个设置功能均能通过新设置页到达，原有数据加载和操作能力没有回归。
- 旧深链接继续有效。
- 自动化测试通过，并完成桌面与移动视口的页面检查。
- 不存在重复入口、不可达面板、设置浮层遮挡内容或横向溢出。
