# 设置详情页返回导航设计

## 目标

在设置详情页标题区域提供清晰、易点击的“← 返回”按钮。用户从对话、日程管理或求职助手进入设置后，点击该按钮应回到进入设置前的页面；Android 系统返回键和浏览器返回行为也应在一次操作内回到同一来源页面。

直接通过 `#settings` 或某个设置子路由打开页面、没有可确认的应用内来源时，返回按钮应安全回到对话页，不能退出 WebView 或跳转到外部页面。

## 界面

- 在 `settingsView` 的标题区域左侧增加返回按钮，按钮文字为“返回”，并带左箭头。
- 使用真实 `button` 元素，提供明确的 `aria-label` 和不小于现有移动端图标按钮的点击区域。
- 返回按钮只属于设置详情页，不加入右上角三项快捷菜单，也不改变设置内部导航的排列方式。

## 路由行为

设置中心在浏览历史中占用一个条目：

1. 从非设置页面进入设置时，继续使用 `pushState` 创建设置条目，并在该条目的 `history.state` 中记录来源 hash。
2. 在主动建议、账号连接、助理身份、Web Search 等设置子项之间切换时，使用 `replaceState` 更新当前设置条目，保留最初的来源 hash，不连续堆积多个设置历史条目。
3. 点击标题区返回按钮时：
   - 如果当前设置条目带有可信的应用内来源，调用浏览历史返回，由现有 `hashchange` 监听器恢复来源页面。
   - 如果页面是直接打开或刷新后没有来源状态，则用 `replaceState` 切换到 `#chat` 并立即激活对话路由。
4. 因为所有设置子项共享一个历史条目，Android 系统返回键也能一次退出设置，而不是逐个回退设置子项。

来源只接受当前工作台已知的非设置路由；无效、外部或设置内部 hash 不作为返回目标。

## 代码边界

- `index.html`：增加返回按钮。
- `styles.css`：增加标题区布局和移动端返回按钮样式。
- `app.js`：在现有工作台导航控制器中封装“进入设置、替换设置子路由、退出设置”的历史规则；页面事件只调用控制器，不直接拼接 hash。
- 静态工作台测试：通过现有 Node 路由测试工具验证历史栈、来源恢复和直接打开时的兜底。

不修改 Android 原生 Activity、服务端 API、数据库或设置项业务逻辑。

## 验收标准

- 从对话页进入设置，点击返回后回到对话页。
- 从日程管理或求职助手进入设置，点击返回后回到对应来源页。
- 在设置内切换多个子项后，点击返回仍一次回到最初来源页。
- Android 系统返回键在设置内一次回到来源页。
- 直接打开 `#settings` 时，页面返回按钮回到对话页。
- 返回按钮在真机竖屏上可见、可点击，不挤压标题或设置导航。
- 原三项快捷菜单及全部设置入口保持不变。
