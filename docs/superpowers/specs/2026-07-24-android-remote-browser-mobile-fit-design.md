# Android 远程浏览器移动端适配设计

## 目标

Android 真机中的远程浏览器需要在不同手机分辨率上完整显示远端桌面，并允许用户滚动远端网页。页面不能再只露出左上角，也不能因为缩放而破坏点击、二维码刷新或文字输入。

## 已确认根因

Android 当前生成的 noVNC 地址包含 `resize=remote`，但服务器使用的
`vnc_lite.html` 不读取该参数。该页面只通过 `scale` 参数控制
`RFB.scaleViewport`，所以现有地址不会触发视口缩放，1080×1920 的远端画布被
384 CSS 像素宽的 Android WebView 裁切。

真机 A/B 验证已经证明：

- 将 noVNC 参数改为 `scale=1` 后，完整远端画布会缩放到手机 WebView 内；
- 远端 Chromium 页面使用 125% 显示比例后，WhatsApp 登录页在手机上仍清晰可读；
- 缩放后点击过期二维码可以正确命中并刷新，触控坐标映射没有失真。

## 方案

### Android noVNC 地址

`ConfigPrefs` 生成远程浏览器地址时使用 `scale=1`，保留自动连接、质量、压缩、
触控点和密码参数。适配由 noVNC 根据当前 WebView 尺寸动态完成，因此不依赖
具体手机分辨率，也不需要把手机尺寸传给服务器。

### 远端页面可读性

Chromium 运行时增加可配置的 `CHROMIUM_DEVICE_SCALE_FACTOR`，默认值为 `1.25`，
并传给 `--force-device-scale-factor`。远端桌面分辨率仍保持 1080×1920；显示比例
只提高浏览器界面和网页内容的可读性。部署配置显式传入 `1.25`，未来可按设备
体验调整而不改代码。

### 滚动和输入

不在 Android WebView 上增加自定义手势拦截。noVNC 已将双指拖动映射为远端鼠标
滚轮；保留这一原生行为可以同时维持：

- 单指点击和拖拽；
- 双指上下滑动远端网页；
- 现有的“输入到远端”文字输入桥；
- 缩放后的正确坐标映射。

远程输入栏提示改为“`双指上下滑动远端页面；先点远端输入框，再在这里输入。`”，
让操作方式在页面内可发现。

## 数据流

1. Android 从服务器地址和应用密码生成带 `scale=1` 的 noVNC URL。
2. WebView 加载 `vnc_lite.html`，noVNC 将 1080×1920 远端画布缩放到当前
   WebView 可视区域。
3. Chromium 以 1.25 的显示比例渲染远端页面。
4. 用户单指操作由 noVNC 转换为远端指针事件；双指上下滑动转换为远端滚轮事件。
5. 手机方向或可视高度变化时，现有 `resize` 处理让 noVNC 重新计算缩放。

## 错误处理

沿用现有的 noVNC 断线检测、重连提示和 WebWorkspace 加载失败提示。本次不改变
登录态、会话存储和远端账号数据。显示比例参数提供默认值，未配置时仍能稳定启动。

## 测试与验收

- Android 单元测试断言远程 URL 使用 `scale=1`，且密码仍正确编码。
- Android 源码回归测试断言远程输入栏展示双指滚动提示。
- Chromium 启动脚本测试断言默认显示比例和启动参数存在。
- Android 全量单元测试和 Chromium 运行时测试通过。
- 构建并安装 Android Debug APK。
- 服务端重建 Chromium 运行时后确认实际启动参数、noVNC URL 和画布尺寸。
- 真机确认 WhatsApp 登录页完整可见、按钮可点、二维码可刷新。
- 使用真实 WebView 触控链路发送双指滑动，在远端长页面确认滚动位置发生变化。

## 不在本次范围

- 不登录或绑定用户的 WhatsApp 账号；
- 不修改 noVNC 上游源码；
- 不按单一手机型号硬编码 WebView 或远端桌面尺寸；
- 不把单指拖动改成页面滚动，以免破坏远端网页中的拖拽交互。
